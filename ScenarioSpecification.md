# Спецификация пакета сценария
Пакет (файл) сценария `<имя_пакета_сценария>.json` хранит все данные для загрузки сценария на backend и последующего использования на frontend.

## Общая структура
Структура пакета сценария:
```json
{
    "name": "<имя_пакета_сценария>",
    "label": "<заголовок_сценария>",
    "description": "<описание_сценария>",
    "icon": "<изображение_иконки>",
    "nodes": {
        "<название_ноды>": {
            "label": "<заголовок_ноды>",
            "content_type": "<тип_содержимого_ноды>",
            "content": {...}
        },
        ...
    },
    "creation_time": 0
}
```

## Переменные сценария (state)
По умолчанию переменные из state хранят текущее состояние, как минимум:
```json
{
  "username": "<имя_пользователя>",
  "loyalty": 50,
  "safety": 50,
  "0": 0,
  "100": 100
}
```
username - имя пользователя
loyalty "Лояльность пассажира" и safety "Рейтинг безопасности" принимают значения от 0 до 100 включительно
0, 100 - константы
Данные значения не могут быть изменены через `set`, а только через соответствующие методы (или не могут быть изменены, если соответствующие методы отсутствуют)

## Ноды: `content_type` и их `content`
Прямой проход по нодам осуществляется последовательно с использованием строкового указателя, изменяемого по `next_node`. 
Ноды выполняются последовательно по принципу конечного автомата кроме:
- [async] асихронных вызовов порождает рекурсивный (одномоментный) обход дочерних нод, НО обычный вызов [async] ноды обрабатывается как вызов обычной ноды. То есть возможны: прямой проход + обычная нода + прямой проход; прямой проход + асинхронная нода + прямой проход; асинхронный проход + асинхронная нода + асинхронный проход.
- [state] вызывается в случае истинности заданных условий состояния, данная нода уникальна во всём сценарии (включая аргументы, кроме `next_node`)
- [resource] ресурсная нода, не может быть вызвана, принмается исключительно как аргумент с полем `resource`. 

### Стартовая нода
[state] `begin` - нода, с которой начинается сценарий, вызывается если игра готова к началу (единственная)
```json
{
  "next_node": "<следующая_нода>"
}
```

### Нода триггер
[state][async] `trigger` - нода, вызываемая если значение state переменной изменяется (по одной на каждый `name`)
```json
{
    "name": "<имя_переменной>",
    "next_node": "<следующая_нода>"
}
```

### Завершающая нода
[state] `end` - нода, которой заканчивается сценарий, вызывается если система игра готова к завершению; `is_completed` передаётся frontend вызовом API backend, как значение успешного (победного) или неуспешного (проигрышного) завершения сценария (одна на `"is_completed": true`, и одна на `"is_completed": false`)
```json
{
    "is_completed": false
}
```


### Нода очищения
`clear` - очищает все отрисованные элементы
```json
{
    "next_node": "<следующая_нода>"
}
```

### Нода изображения
[resource] `image` - предоставляет base64 изображения
```json
{
  "resource": "<base64_изображения>"
}
```


### Нода сцены
`scene` - устанавливает фон и текст внизу фона (диалоговое окно) В тексте и заголовке могут использоваться переменные `state` в виде плейсхолдеров (например `{username}`). Переход к следующей ноде, после клика мышкой. Если text/image is null, то текст/изображение не меняется. Если text/image is "", то текст/изображение очищаются.
```json
{
  "image_node": "<нода_изображения>",
  "label": "<заголовок>"
  "text": "<текст>"
  "next_node": "<следующая_нода>"
}
```

### Нода выбора
`choice` - устанавливает список доступных выборов (диалоговое окно) В топике и текстах могут использоваться переменные `state` в виде плейсхолдеров (например `{username}`). Переход к следующей соответсвенной ноде, после выбора
```json
{
  "topic": "<текст_предмет_выбора>",
  "choice": [
    {
      "text": "<текст_выбора>",
      "next_node": "следующая_нода_при_выборе"
    },
    ...
  ]
}
```

### Нода временного выбора
`time_choice` - устанавливает список доступных выборов (диалоговое окно) В топике и текстах могут использоваться переменные `state` в виде плейсхолдеров (например `{username}`). Переход к следующей соответсвенной ноде, после выбора
```json
{
  "topic": "<текст_предмет_выбора>",
  "choice": [
    {
      "text": "<текст_выбора>",
      "next_node": "следующая_нода_при_выборе"
    },
    ...
  ],
  "time": 0,
  "timeout_node": "нода_бездействия"
}
```

### Нода уведомления
[async] `notice` - уведомление на ТСД (Терминал Сбора Данных), отображается в угловой части экрана. В тексте могут использоваться переменные `state` в виде плейсхолдеров (например `{username}`)
```json
{
  "text": "<текст_уведомления>",
  "next_node": "<следующая_нода>"
}
```

### Нода изменения шкалы лояльности
[async] `loyalty` - изменение уровня "Лояльности пассажира"
```json
{
  "delta": 0,
  "next_node": "<следующая_нода>"
}
```

### Нода изменения рейтинга безопасности
[async] `safety` - изменение уровня "Рейтинг безопасности"
```json
{
  "delta": 0,
  "next_node": "<следующая_нода>"
}
```

### Нода создания таймера
`start_timer` - создание и запуск таймера (может быть несколько одновременно). По окончанию/перыванию таймера асинхронно вызывается [async] нода (или не вызывается, если null)
```json
{
  "name": "<название_таймера>",
  "label": "<отображаемый_заголовок_таймера>",
  "time": 0,
  "interruption_node": "<следующая_нода_при_прерывании_async>",
  "finish_node": "<следующая_нода_при_завершении_async>",
  "next_node": "<следующая_нода_async>"
}
```

### Нода прерывания таймера
[async] `interrupt_timer` - прерывание таймера
```json
{
  "name": "<название_таймера>",
  "next_node": "<следующая_нода>"
}
```

### Нода принудительного завершения таймера
[async] `kill_timer` - принудительное завершение таймера (завершение без вызова `interrupt_node`)
```json
{
  "name": "<название_таймера>",
  "next_node": "<следующая_нода>"
}
```


### Нода принудительного завершения всех таймеров
[async] `kill_all_timers` - принудительное завершение всех таймеров (завершение без вызова `interrupt_node`)
```json
{
  "next_node": "<следующая_нода>"
}
```


### Нода достижения (ачивки)
[async] `achievement` - получение достижения (ачивки); на frontend вызов API backend
```json
{
  "name": "<название_достижения>",
  "label": "<заголовок_достижения>",
  "description": "<описание_достижения>",
  "icon": "<изображение_иконки>",
  "score_delta": 0
  "next_node": "<следующая_нода>"
}
```

### Нода перехода
[async] `goto` - установка строкового указателя текущей ноды основного потока, предполагается применение для воздействия на основной поток событий из асинхронного вызова. Применять с осторожностью!
```json
{
  "goto_node": "<следующая_нода_основного_потока>",
  "next_node": "<следующая_нода_текущего_потока>"
}
```

### Нода принудительного вызова основного потока
[async] `call` - принудительная обработка итерации основного потока, предполагается применение для воздействия на основной поток событий из асинхронного вызова в связке `goto` + `call` чтобы `goto` нода установила текущий строковый указатель ноды основного потока и `call` принудительно обработала её сразу, а не после завершения выполняемой ноды текущего потока. Т.е. на примере: показана `scene` (без `choice` кнопка "Далее", а не список выбора), ожидается нажатие кнопки "Далее", простой асинхронный вызов `goto`, вызваннй как асинхронная нода `finish_node` таймера, установит текущей строковый указатель основного потока на `goto_node` и на неё получится перейти только после нажатия кнопки "Далее", а `goto`+`call` принудительно прервёт показ текущей `scene` и продолжит выполнение основного потока с `goto_node`. Применять с осторожностью!
```json
{
  "next_node": "<следующая_нода_текущего_потока>"
}
```

### Нода переменной
[async] `set` - установка значения state переменной (за исключением переменных по умолчанию)
```json
{
    "name": "<имя_переменной>",
    "value": ...,
    "next_node": "<следующая_нода>"
}
```

### Нода условия "равно"
[async] `if_equals` - проверка на равность значений state переменных и установка соответственной ноды
```json
{
    "name_a": "<имя_переменной_A>",
    "name_b": "<имя_переменной_B>",
    "neq_node": "<следующая_нода_если_не_равны>",
    "next_node": "<следующая_нода_если_равны>"
}
```

### Нода условия "больше"
[async] `if_compare` - проверка на то, что значение переменных state `A > B` и установка соответственной ноды
```json
{
    "name_a": "<имя_переменной_A>",
    "name_b": "<имя_переменной_B>",
    "ncp_node": "<следующая_нода_если_A_не_больше_B>",
    "next_node": "<следующая_нода_если_A_больше_B>"
}
```
