# Спецификация пакета сценария
Пакет (файл) сценария `<имя_пакета_сценария>.json` хранит все данные для загрузки сценария на backend и последующего использования на frontend.

## Общая структура
Структура пакета сценария:
```json
{
    "name": "<имя_пакета_сценария>",
    "label": "<заголовок_сценария>",
    "description": "<описание_сценария>",
    "icon": "<изображение_иконки>",
    "nodes": {
        "<название_ноды>": {
            "label": "<заголовок_ноды>",
            "content_type": "<тип_содержимого_ноды>",
            "content": {...}
        },
        ...
    },
    "images": {
        "<название_изображения>": "<base64_изображения>",
        ...
    },
    "achievements": {
        "<название_достижения>": {
            "label": "<заголовок_достижения>",
            "description": "<описание_достижения>",
            "icon": "<изображение_иконки>",
            "score_delta": 0
        }
    }
    "creation_time": 0
}
```

## Переменные сценария (state)
По умолчанию переменные из state хранят текущее состояние, как минимум:
```json
{
  "username": "<имя_пользователя>",
  "loyalty": 50,
  "safety": 50
}
```
loyalty "Лояльность пассажира" и safety "Рейтинг безопасности" принимают значения от 0 до 100 включительно

## Ноды: `content_type` и их `content`
Ноды выполняются последовательно по принципу конечного автомата кроме:
- [async] асихронных вызовов порождает рекурсивный обход дочерних нод, НО обычный вызов [async] ноды обрабатывается как вызов обычной ноды
- [state] вызывается на каждой итерации, в случае истинности заданных условий (определенное условие может быть только одно на весь сценарий, иначе ошибка) прерывает/начинает основной поток выполнения, устанавливая данную ноду текущей.

### Стартовая нода
[state] `begin` - нода, с которой начинается сценарий, вызывается если игра готова к началу
```json
{
  "next_node": "<следующая_нода>"
}
```

### Нода нелояльности
[state] `loyalty_defeat` - нода, вызываемая если уровень "Лояльности пассажира" достигает 0
```json
{
    "next_node": "<следующая_нода>"
}
```

### Нода небезопасности
[state] `safety_defeat` - нода, вызываемая если уровень "Рейтинга безопасности" достигает 0
```json
{
    "next_node": "<следующая_нода>"
}
```

### Завершающая нода
[state] `end` - нода, которой заканчивается сценарий, вызывается если система игра готова к завершению; `is_completed` передаётся frontend вызовом API backend, как значение успешного завершения сценария
```json
{
    "is_completed": false
    "next_node": null
}
```


### Нода очищения
`clear` - очищает все отрисованные элементы
```json
{
    "next_node": "<следующая_нода>"
}
```

### Нода информационной страницы
`page` - содержит информационную страницу (без фона) и простой набор блоков текст + подписанное изображение (отсутствующее имеет значение `null`) и кнопку "Продолжить". В тексте могут использоваться переменные `state` в виде плейсхолдеров (например `%username%`)
Предназначен для стартовых инструкций, теоретических материалов, завершающего пояснения.
```json
{
  "data": [
    {
      "text": "<текст ноды>",
      "image": "<изображение>",
      "sign": "<подпись изображения>"
    },
    ...
  ],
  "next_node": "<следующая_нода>"
}
```

### Нода изображения
`image` - задаёт фон изображения
```json
{
  "image": "<изображение>",
  "next_node": "<следующая_нода>"
}
```

### Нода текста
`text` - устанавливает текст внизу фона (диалоговое окно) В тексте и заголовке могут использоваться переменные `state` в виде плейсхолдеров (например `%username%`). Переход к следующей ноде, после клика мышкой
```json
{
  "label": "<заголовок>"
  "text": "<текст>"
  "next_node": "<следующая_нода>"
}
```

### Нода выбора
`choice` - устанавливает список доступных выборов (диалоговое окно) В топике и текстах могут использоваться переменные `state` в виде плейсхолдеров (например `%username%`). Переход к следующей соответсвенной ноде, после выбора
```json
{
  "topic": "<текст_предмет_выбора>",
  "choice": [
    {
      "text": "<текст_выбора>",
      "next_node": "следующая_нода_при_выборе"
    },
    ...
  ]
}
```

### Нода уведомления
[async] `notice` - уведомление на ТСД (Терминал Сбора Данных), отображается в угловой части экрана. В тексте могут использоваться переменные `state` в виде плейсхолдеров (например `%username%`)
```json
{
  "text": "<текст_уведомления>",
  "next_node": "<следующая_нода>"
}
```

### Нода изменения шкалы лояльности
[async] `loyalty` - изменение уровня "Лояльности пассажира"
```json
{
  "delta": 0,
  "next_node": "<следующая_нода>"
}
```

### Нода изменения рейтинга безопасности
[async] `safety` - изменение уровня "Рейтинг безопасности"
```json
{
  "delta": 0,
  "next_node": "<следующая_нода>"
}
```

### Нода создания таймера
`start_timer` - создание и запуск таймера (может быть несколько одновременно). По окончанию/перыванию таймера асинхронно вызывается [async] нода (или не вызывается, если null)
```json
{
  "name": "<название_таймера>"
  "label": "<отображаемый_заголовок_таймера>",
  "interruption_node": "<следующая_нода_при_прерывании_async>",
  "next_node": "<следующая_нода_при_завершении_async>"
}
```

### Нода прерывания таймера
`interrupt_timer` - прерывание таймера
```json
{
  "name": "<название_таймера>",
  "next_node": "<следующая_нода>"
}
```

### Нода достижения (ачивки)
[async] `achievement` - получение достижения (ачивки); на frontend вызов API backend
```json
{
  "name": "<название_достижения>",
  "next_node": "<следующая_нода>"
}
```

### Нода перехода
[async] `goto` - установка текущей ноды, предполагается применение для воздействия на основной поток событий из асинхронного вызова и бездействие для вызова из основного потока
```json
{
  "goto_node": "<следующая_нода_основного_потока>",
  "next_node": null
}
```

### Нода переменной
[async] `set` - установка значения state переменной
```json
{
    "name": "<имя_переменной>",
    "value": ...,
    "next_node": "<следующая_нода>"
}
```

### Нода условия "равно"
[async] `if_equals` - проверка на равность значений state переменных и установка соответственной ноды
```json
{
    "name_a": "<имя_переменной_A>",
    "name_b": "<имя_переменной_B>",
    "neq_node": "<следующая_нода_если_не_равны>",
    "next_node": "<следующая_нода_если_равны>"
}
```

### Нода условия "больше"
[async] `if_compare` - проверка на то, что значение переменных state A > B и установка соответственной ноды
```json
{
    "name_a": "<имя_переменной_A>",
    "name_b": "<имя_переменной_B>",
    "ncp_node": "<следующая_нода_если_A_не_больше_B>",
    "next_node": "<следующая_нода_если_A_больше_B>"
}
```
